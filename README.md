# 日本株スクリーニングアプリ（須田忠雄事務所ルール版）

須田忠雄事務所のルールとして挙げられた以下8項目のいずれかに合致した
日本株を探すスクリーニングアプリ。

1. 札幌・福岡・名古屋証券取引所から東証に上場市場を移した
2. スタンダード市場・グロース市場からプライム市場へ市場区分を変更した
3. 売り上げが大幅に増えた
4. ストップ高が出た
5. 四半期(本決算)が会社予想よりも増えていた
6. 新しく工場や店舗を作った
7. 株式分割があった
8. 爆発的に売り上げが伸びた

## 現在の実装状況

| # | 項目 | 実装 | 判定方法 |
|---|---|---|---|
| 4 | ストップ高 | ✅ | `/equities/bars/daily` の `UL` フラグ |
| 3, 8 | 売上高の大幅増加/爆発的増加 | ✅ | `/fins/summary` の `Sales` 前年同期比（+20%以上=大幅、+50%以上=爆発的） |
| 5 | 本決算が会社予想を上回った | ✅ | `/fins/summary` の `NP` 実績 と 直前開示の `FNP`（会社予想） を比較 |
| 7 | 株式分割・併合 | ✅ | `/equities/bars/daily` の `AdjFactor` の変化を検知 |
| 2 | スタンダード/グロース→プライムの市場変更 | ✅ | `/equities/master` は `date` パラメータで過去時点の市場区分を遡って返す（2026-07-28実機確認）。日次スナップショットを比較して変更日を検出 |
| 1 | 東証移籍（札幌/福岡/名古屋→東証） | ⚠️ 部分実装 | TDnet開示タイトルを「地方取引所からの上場廃止」+「東証への上場」の句で判定。地方取引所のデータ自体はJ-Quants圏外なので、新規IPOと完全には区別できない。過去1年の実データでは該当ゼロ件（レアな事象） |
| 6 | 新工場・新店舗の設置 | ⚠️ 部分実装 | TDnet開示タイトルのキーワード検出（新工場/新規出店等、閉鎖・中止系は除外）。タイトルのみの判定なので誤検出の可能性があり、詳細列の開示タイトルで内容を確認する運用が前提 |

追加で、須田事務所ルールの8項目には無いが要望のあった項目も実装済み: 自己資本比率60%以上、経常利益が4年で2倍以上、業績予想の下方修正（除外フィルター用）、業種、時価総額、PER（予想）、PBR、配当利回り、推定上場日（近似）。

「東証移籍」「新工場・新店舗」はTDnet（適時開示情報閲覧サービス）の非公式ミラーAPI
（`src/tdnet_client.py`、個人運営 https://webapi.yanoshin.jp/ ）を使っている。
個人運営のため予告なく停止する可能性があり、その場合は該当2ルールだけ結果が
得られなくなる（他のルールは正常に動作し続ける。`pipeline.run_screening` は
TDnet取得失敗時に警告を出して処理を継続する）。停止した場合の代替案:

- TDnet公式サイト(https://www.release.tdnet.info/)を直接スクレイピング
- JPXの有料TDnet API（法人向け、詳細: https://www.jpx.co.jp/markets/paid-info-listing/tdnet/02.html）に切り替え

「オーナー経営」「取引先」は未実装。大株主・取引先情報はEDINETの有価証券報告書
本文に自由記述で書かれているだけで構造化データが無く、文書ごとの自然言語解析が
必要になるため今回は見送っている。

## セットアップ

```bash
pip install -r requirements.txt
cp .env.example .env
# .env を編集して J-Quants ダッシュボード（設定 > APIキー）で発行したAPIキーを設定
streamlit run app.py
```

### V2移行について

2026年1月にJ-Quants APIは V2 に移行し、認証方式が
「メールアドレス/パスワード→リフレッシュトークン/IDトークン」から
「ダッシュボードで発行するAPIキーを `x-api-key` ヘッダーに載せる」方式に変わった。
旧V1のエンドポイント（`/v1/token/auth_user` 等）は410 Goneで廃止済み。
エンドポイントパスやレスポンスの列名も変更されている
（詳細: https://jpx-jquants.com/ja/spec/migration-v1-v2 ）。
本コードは移行後のV2仕様に合わせて実装している。

### J-Quants Lightプランの制約

2026-07-28にFreeプランからLightプランに切り替え済み（`JQUANTS_API_CALLS_PER_MINUTE`
の値は `src/config.py` 参照）。

- API呼び出しは **60件/分** まで（本アプリはレート制限を自動で待機しながら守る。429を
  受けた場合は65秒待って自動リトライする）
- 遅延配信なし・過去5年分のデータが取得可能
- 日経225・信用取引・空売りデータ等は対象外（本アプリでは使用していないため影響なし）

料金・仕様は変更される可能性があるため、プラン変更や運用方針を変える前に必ず公式ページで最新情報を確認すること（`CLAUDE.md` 記載のリンク参照）。

### 実行前に必ず確認すること

`src/rules.py` の列名定数（`UL`、`AdjFactor`、`FNP` など）はJ-Quants V2の公式APIリファレンスで
実機確認済み（2026-07-28）だが、サービス側の仕様変更で再度ズレる可能性があるため、
心配な場合は以下を実行して実際に返ってくる列名を目視確認すること。

```bash
python scripts/inspect_schema.py
```

出力された列名が `src/rules.py` の定数と異なる場合は、そちらを実際の列名に合わせて修正する。

## 使い方

1. `streamlit run app.py` を実行
2. 開始日・終了日を指定（前日までのデータを取得可能）
3. 実行前に「対象にする条件」「最低何項目に合致するか」「下方修正歴の除外」を選択
4. 「スクリーニング実行」を押すと、該当日数分の株価・決算開示・市場区分・TDnet開示情報を取得して条件判定
5. 合致した銘柄ごとに時価総額・PER・PBR・配当利回り・推定上場日を追加取得
6. 結果は銘柄単位の集計テーブル（列見出しクリックでソート可能）で表示され、CSVでダウンロード可能。個別イベントの一覧は展開パネルで確認できる

初回実行時は対象期間の日数分だけAPI呼び出しが発生するため、レート制限により時間がかかる（例: 30日分なら日次データ取得だけで数分程度、さらに合致銘柄ごとの追加取得が加わる）。一度取得したデータは `data/cache/` にキャッシュされ、以降の再実行（同日中）では再取得しない。
