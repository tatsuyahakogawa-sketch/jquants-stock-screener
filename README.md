# 日本株スクリーニングアプリ（須田忠雄事務所ルール版）

須田忠雄事務所のルールとして挙げられた以下8項目のいずれかに合致した
日本株を探すスクリーニングアプリ。

1. 札幌・福岡・名古屋証券取引所から東証に上場市場を移した
2. スタンダード市場・グロース市場からプライム市場へ市場区分を変更した
3. 売り上げが大幅に増えた
4. ストップ高が出た
5. 四半期(本決算)が会社予想よりも増えていた
6. 新しく工場や店舗を作った
7. 株式分割があった
8. 爆発的に売り上げが伸びた

## 現在の実装状況

| # | 項目 | 実装 | 判定方法 |
|---|---|---|---|
| 4 | ストップ高 | ✅ | `/equities/bars/daily` の `UL` フラグ |
| 3, 8 | 売上高の大幅増加/爆発的増加 | ✅ | `/fins/summary` の `Sales` 前年同期比（+20%以上=大幅、+50%以上=爆発的） |
| 5 | 本決算が会社予想を上回った | ✅ | `/fins/summary` の `NP` 実績 と 直前開示の `FNP`（会社予想） を比較 |
| 7 | 株式分割・併合 | ✅ | TDnet開示タイトルのキーワード検出（「株式分割」「株式併合」）。株価調整係数(`AdjFactor`)の変化を見る方法だと効力発生日（発表からかなり後）しか検知できず、好材料としての株価反応を先取りできないため、発表日ベースに変更した |
| 2 | スタンダード/グロース→プライムの市場変更 | ✅ | TDnet開示タイトルのキーワード検出（「プライム市場への市場区分変更」の申請・承認）。実際の変更日（効力発生日）は発表からかなり後になるため、株式分割と同様に発表日ベースに変更した |
| 1 | 東証移籍（札幌/福岡/名古屋→東証） | ⚠️ 部分実装 | TDnet開示タイトルを「地方取引所からの上場廃止」+「東証への上場」の句で判定。地方取引所のデータ自体はJ-Quants圏外なので、新規IPOと完全には区別できない。過去1年の実データでは該当ゼロ件（レアな事象） |
| 6 | 新工場・新店舗の設置 | ⚠️ 部分実装 | TDnet開示タイトルのキーワード検出（新工場/新規出店等、閉鎖・中止系は除外）。タイトルのみの判定なので誤検出の可能性があり、詳細列の開示タイトルで内容を確認する運用が前提 |

追加で、須田事務所ルールの8項目には無いが要望のあった項目も実装済み: 自己資本比率60%以上、経常利益が4年で2倍以上、
PBR1倍以下（開示日時点の`BPS`と直近終値から計算）、四半期決算2期連続増収増益（`/fins/summary` の `Sales`・`OdP`
の前年同期比増加が2期連続。「対象にする条件」でPBR1倍以下と組み合わせて選べば、両方に合致した銘柄だけを
絞り込める）、業績予想の下方修正（除外フィルター用）、業種、時価総額、PER（予想）、PBR、配当利回り、推定上場日（近似）、
大型・大口受注の発表、世界初の製品・サービスの発表（いずれもTDnet開示タイトルのキーワード検出）。

「東証移籍」「新工場・新店舗」はTDnet（適時開示情報閲覧サービス）の非公式ミラーAPI
（`src/tdnet_client.py`、個人運営 https://webapi.yanoshin.jp/ ）を使っている。
個人運営のため予告なく停止する可能性があり、その場合は該当2ルールだけ結果が
得られなくなる（他のルールは正常に動作し続ける。`pipeline.run_screening` は
TDnet取得失敗時に警告を出して処理を継続する）。停止した場合の代替案:

- TDnet公式サイト(https://www.release.tdnet.info/)を直接スクレイピング
- JPXの有料TDnet API（法人向け、詳細: https://www.jpx.co.jp/markets/paid-info-listing/tdnet/02.html）に切り替え

「オーナー経営」「取引先」は未実装。大株主・取引先情報はEDINETの有価証券報告書
本文に自由記述で書かれているだけで構造化データが無く、文書ごとの自然言語解析が
必要になるため今回は見送っている。

## セットアップ

```bash
pip install -r requirements.txt
cp .env.example .env
# .env を編集して J-Quants ダッシュボード（設定 > APIキー）で発行したAPIキーを設定
streamlit run app.py
```

`src/`以下のコードを更新した場合、Streamlitのホットリロードはapp.py本体は再実行するがサブモジュール（`pipeline.py`, `excel_export.py`等）の変更を反映しないことがあるため、コード修正後はプロセスを完全に再起動（Ctrl+Cで停止して`streamlit run app.py`を再実行）すること。

### 複数PCでの利用・クラウドデプロイ

複数のPCで作業する場合、各PCでローカルにStreamlitを起動する方式は「pull忘れ」「プロセス再起動忘れ」「PCごとのキャッシュのズレ」で結果が食い違いやすい。代わりにStreamlit Community Cloud（無料）にデプロイし、GitHubリポジトリに接続しておけば、どのPCからプッシュしてもクラウド側が自動的に再デプロイされ、常に同じ1つのアプリを見ることになる。

デプロイ手順:
1. https://share.streamlit.io/ でGitHubアカウント連携し、このリポジトリ（プライベートでも可）を指定してアプリを作成
2. アプリの管理画面「Settings > Secrets」に `.streamlit/secrets.toml.example` の内容を参考に、`app_password`（アプリの合言葉）・`JQUANTS_API_KEY`・`EDINET_API_KEY` を設定する
3. 以降はGitHubにプッシュするたびに自動で再デプロイされる

`app_password`を設定すると、アプリを開いたときにパスワード入力画面が出る（`app.py`の`_check_password`）。これはURLを知っている第三者が自分のAPIキーでレート制限を消費してしまうのを防ぐための簡易ゲートで、ローカル実行時（`.streamlit/secrets.toml`を作らない場合）は認証をスキップする。

### V2移行について

2026年1月にJ-Quants APIは V2 に移行し、認証方式が
「メールアドレス/パスワード→リフレッシュトークン/IDトークン」から
「ダッシュボードで発行するAPIキーを `x-api-key` ヘッダーに載せる」方式に変わった。
旧V1のエンドポイント（`/v1/token/auth_user` 等）は410 Goneで廃止済み。
エンドポイントパスやレスポンスの列名も変更されている
（詳細: https://jpx-jquants.com/ja/spec/migration-v1-v2 ）。
本コードは移行後のV2仕様に合わせて実装している。

### J-Quants Lightプランの制約

2026-07-28にFreeプランからLightプランに切り替え済み（`JQUANTS_API_CALLS_PER_MINUTE`
の値は `src/config.py` 参照）。

- API呼び出しは **60件/分** まで（本アプリはレート制限を自動で待機しながら守る。429を
  受けた場合は65秒待って自動リトライする）
- 遅延配信なし・過去5年分のデータが取得可能
- 日経225・信用取引・空売りデータ等は対象外（本アプリでは使用していないため影響なし）

料金・仕様は変更される可能性があるため、プラン変更や運用方針を変える前に必ず公式ページで最新情報を確認すること（`CLAUDE.md` 記載のリンク参照）。

### 実行前に必ず確認すること

`src/rules.py` の列名定数（`UL`、`AdjFactor`、`FNP` など）はJ-Quants V2の公式APIリファレンスで
実機確認済み（2026-07-28）だが、サービス側の仕様変更で再度ズレる可能性があるため、
心配な場合は以下を実行して実際に返ってくる列名を目視確認すること。

```bash
python scripts/inspect_schema.py
```

出力された列名が `src/rules.py` の定数と異なる場合は、そちらを実際の列名に合わせて修正する。

## 使い方

1. `streamlit run app.py` を実行
2. 開始日・終了日を指定（前日までのデータを取得可能）
3. 実行前に「対象にする条件」「最低何項目に合致するか」「下方修正歴の除外」を選択
4. 「スクリーニング実行」を押すと、該当日数分の株価・決算開示・市場区分・TDnet開示情報を取得して条件判定
5. 合致した銘柄ごとに時価総額・PER・PBR・配当利回り・推定上場日を追加取得
6. 結果は銘柄単位の集計テーブル（列見出しクリックでソート可能）で表示され、CSVでダウンロード可能。個別イベントの一覧は展開パネルで確認できる

初回実行時は対象期間の日数分だけAPI呼び出しが発生するため、レート制限により時間がかかる（例: 30日分なら日次データ取得だけで数分程度、さらに合致銘柄ごとの追加取得が加わる）。一度取得したデータは `data/cache/` にキャッシュされ、以降の再実行（同日中）では再取得しない。

売上高の大幅/爆発的増加・四半期決算2期連続増収増益・経常利益4年倍増の4条件（画面上は紫色のボタン、`pipeline.YOY_LOOKBACK_RULES`）は前年同期比較のため決算データを数年分遡って取得する必要があり、特に時間がかかる。これらを選択しない場合は選択期間分のみの取得になり高速。

## 個別銘柄のExcel出力（企業詳細・実行表）

画面下部の「個別銘柄のExcel出力」から、銘柄コードを入力して以下2種類のExcelを自動生成できる（`src/excel_export.py`）。ETF・REIT・ETN等（`equities/master`の`ProdCat`が`011`＝内国株式の普通株式以外）は事業概要・決算等の対象外のため、生成前に警告を表示してブロックする。

- **企業詳細**: 証券コード・会社名・時価総額・PBR・PER・配当利回り・株価・発行済株式総数・市場区分・決算月を1社1シートのテンプレート（`templates/company_detail_template.xlsx`）に埋め込む。事業概要・大株主・潜在株式の状況はEDINET（後述）から取得できれば埋め込む。株式分割・併合があれば、その日付（C12、増資および潜在株式欄に追記）も埋める
- **実行表**: 元の実行表（年度×四半期の売上・経常利益・株価マトリクス、利益率・検算の数式付き）と同じレイアウト・書式のテンプレート（`templates/execution_table_template.xlsx`）に値だけを埋め込む。年度列は7枠（C,E,G,I,K,M,O）あり、C列から左詰めで実績年度を並べ、直近の会社予想年度（本決算開示時点の`NxFSales`/`NxFOdP`）はその直後の列に置く。Lightプランで取れる実績は最大5年分のため、6枠のうち末尾（右側）が空欄になることがある（その場合、空欄の列の「検算」行の数式は#DIV/0!表示になる）。決算期が到来していない進行中の年度（例:決算月が3月以外の会社）は、直近の開示に含まれる会社予想(FSales/FOdP)で「決算」行を埋め、本決算が実際に開示されれば次回生成時に実績値へ置き換わる。売上（億円）は小数点以下切り捨て、経常利益は小数点2桁まで。株式分割・併合があった日付（株価データのAdjFactorの変化から検出、Q10に追記）も埋める。「備考：トピックス」「1.悪い所」「2.納品先、取引先」「3.価格が上下した理由」「4.将来性」「5.その他」の定性コメント欄はいずれも自動転記せず空欄のままにする（分析者が手動で記入する運用。EDINET・公式サイトからの転記が必要な場合はREADME.mdの「会社公式サイトからの追記」の運用に従いClaude Codeとの対話で行う）。株式分割・併合は契約プランの取得可能期間（Lightは過去5年）より前のものは株価データが無く検出できない

### EDINET連携（事業概要・大株主・潜在株式・事業等のリスク・経営方針）

上記の自由記述項目は、EDINET（金融庁）の有価証券報告書から実際に開示されているテキストをそのまま抜き出して埋める（`src/edinet_client.py`）。要約や言い換えは行わない。使うには無料のAPIキー（電話番号登録必須、
https://api.edinet-fsa.go.jp/api/auth/index.aspx?mode=1 ）を発行し、`.env`に`EDINET_API_KEY=...`を設定する。未設定の場合はこれらの項目だけ空欄になり、他の機能には影響しない。

- 事業の内容・大株主の状況・潜在株式の状況・事業等のリスク・経営方針等はいずれもXBRLの「テキストブロック」要素としてHTML（大株主は表）がまるごと入っている形式で、個別の構造化データとしては取得できない（EDINETタクソノミの仕様上の制約）
- 大株主は有報の開示どおり上位10位まで（「上位6位まで」ではない）。表のHTMLをパースして株主名・株数・比率の列に正規化している
- 潜在株式・大株主・事業等のリスク・経営方針のタグが見つからない場合、「開示が無い（該当なし）」と「取得に失敗した」を区別できないため、いずれも空欄のままにする（無いものを断定的に「該当なし」と書かない）
- 主要な顧客（納品先・取引先）の情報は開示されていない会社も多く、取得できないことがある
- EDINETの書類一覧APIは日付単位でしか検索できないため、決算期末から提出期限（通常3ヶ月以内）付近の期間を走査して該当書類を探す。古い書類を含めた全期間走査はしていない

いずれも生成後、ボタンからExcelファイルとしてダウンロードする。

### Supabase連携（キャッシュ永続化、任意設定）

`data/cache/` のキャッシュはStreamlit Community Cloud上ではデプロイ毎にコンテナが
作り直されて消えてしまい、次回アクセス時にまた最初から取得し直しになる。
SUPABASE_URL・SUPABASE_KEYを設定すると、同じキャッシュデータをSupabase
（無料枠のPostgres、REST API経由）にも保存し、ローカルキャッシュが無いときは
そちらから読み直す（`src/cache.py`）。未設定でもアプリは動作する（ローカル
キャッシュのみになり、デプロイ毎にまた取得し直しになるだけ）。

設定手順:
1. https://supabase.com で無料アカウント・プロジェクトを作成
2. SQL Editorで以下を実行してテーブルを作成する
   ```sql
   create table jquants_cache (
       endpoint text not null,
       cache_key text not null,
       data text not null,
       updated_at timestamptz not null default now(),
       primary key (endpoint, cache_key)
   );
   ```
3. プロジェクトの「Settings > API」からProject URL・API Key（`service_role`推奨。
   RLSを有効にした場合は`anon`キーだと書き込みがブロックされる点に注意）を取得
4. ローカルは`.env`に、Streamlit Cloudは「Settings > Secrets」に
   `SUPABASE_URL`・`SUPABASE_KEY`を設定する（`.env.example`/
   `.streamlit/secrets.toml.example`参照）

### 地方株ページ（地方証券取引所単独上場企業の発見支援）

サイドバーの「地方株」ページ（`pages/地方株.py`）は、まだ注目されていない
地方（札幌・福岡・名古屋）単独上場企業を見つけるための機能。J-Quantsは
地方取引所単独上場企業を一切対象としないため（CLAUDE.md「データ対象範囲の
制約」参照）、代わりにTDnet開示の`markets_string`列（開示時点でどの取引所に
上場していたかを示す文字。東=東証, 福=福証, 名=名証, 札=札証）で地方単独
上場企業を特定する（`src/regional_stocks.py`）。

表示内容:
- 地方単独上場企業の新規上場・重複上場（申請/承認/実施の段階を区別）
- 東証への新規上場・重複上場・市場変更の発表（🔴最重要イベントとして区別）
- M&A・TOB・MBO・資本業務提携・出資・大型受注・大型契約等の大型イベント

時価総額（株価×発行済株式数）は発行済株式数を取得する手段が無いため算出
できず、掲載しない。代わりに「現在値」として株価のみを表示する。福証単独
上場企業のみyfinanceの`.F`サフィックスで取得できることを実機確認済み
（2026-08-13、9388で確認）。名証・札証単独上場企業、および新規上場直後の
英数字コード銘柄（`482A0`等）はyfinanceでも取得できないため「取得不可」
と表示する（誤った
推測値を出さないため）。

画面の「最新情報を取得（更新）」ボタンを押すと、前回スキャン済み日付の翌日
から今日までのTDnet開示だけを追加取得し、保存済みデータに追記する（初回は
`REGIONAL_LISTING_LOOKBACK_YEARS`年分＝デフォルト3年を遡る）。ボタンを押さ
ない限りTDnet・yfinanceへは通信しないため、通常のページ表示は保存済みデータ
の読み込みのみで軽い。

### 会社公式サイトからの追記（Claude Codeとの対話で行う運用）

「2.納品先、取引先」「4.将来性」「1.悪い所」等、EDINET・J-Quantsでも埋まらなかった項目は、
Claude Codeに銘柄コード（または会社名）を伝えて「HPを見て入力して」と依頼する運用とする。
検索エンジンの自動スクレイピングはDuckDuckGo・Google共にボット判定でブロックされ、
キー不要の方法では信頼できないことを確認済み（2026-07-30）。そのためアプリのコードには
組み込まず、その都度Claude CodeがWeb検索・該当ページの閲覧を行い、実際に開示されている
内容（会社概要ページの主要得意先一覧、中期経営方針ページの数値目標・自社の課題等）を
出典URL付きでExcelに直接書き込む。要約・言い換えはせず、公式サイトに書かれている内容を
そのまま転記する（LLMによる推測・捏造は行わない）。「3.価格が上下した理由」は公式サイトにも
載っていない市況解釈のため、この方法でも埋めない。

事業概要・主要株主・増資情報等の自由記述で、EDINET・公式サイトのいずれからも実データが
取れない項目は空欄のままになる。ダウンロード後、Excel上で残りを手動追記・印刷すること。
